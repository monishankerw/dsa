1. How it works internally

When a controller throws an exception, DispatcherServlet passes it through a chain of HandlerExceptionResolvers:

  1. ExceptionHandlerExceptionResolver looks for @ExceptionHandler methods, first in the controller, then in @ControllerAdvice.
  2. ResponseStatusExceptionResolver handles @ResponseStatus and ResponseStatusException.
  3. DefaultHandlerExceptionResolver maps built-in Spring exceptions (such as HttpRequestMethodNotSupportedException) to 4xx codes.
  4. If nothing handles it, the error goes to /error (BasicErrorController), which returns the default JSON or Whitelabel page.
Interview line: centralized handling with @RestControllerAdvice keeps controllers clean and gives every API a consistent error format.

3. Custom exception and global handler

public class ResourceNotFoundException extends RuntimeException {
    public ResourceNotFoundException(String message) { super(message); }
}

public record ErrorResponse(Instant timestamp, int status, String code,
                            String message, String path, Map<String, String> errors) {}
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(ResourceNotFoundException ex,
                                                        HttpServletRequest req) {
        return build(HttpStatus.NOT_FOUND, "NOT_FOUND", ex.getMessage(), req, null);
    }

    // @Valid on @RequestBody fails
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(MethodArgumentNotValidException ex,
                                                          HttpServletRequest req) {
        Map<String, String> errors = new LinkedHashMap<>();
        ex.getBindingResult().getFieldErrors()
          .forEach(f -> errors.put(f.getField(), f.getDefaultMessage()));
        return build(HttpStatus.BAD_REQUEST, "VALIDATION_FAILED", "Invalid request", req, errors);
    }

    // @Validated on @PathVariable / @RequestParam fails
    @ExceptionHandler(ConstraintViolationException.class)
    public ResponseEntity<ErrorResponse> handleConstraint(ConstraintViolationException ex,
                                                          HttpServletRequest req) {
        return build(HttpStatus.BAD_REQUEST, "CONSTRAINT_VIOLATION", ex.getMessage(), req, null);
    }

    // Fallback: never leak stack traces to clients
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleAll(Exception ex, HttpServletRequest req) {
        log.error("Unhandled exception", ex);
        return build(HttpStatus.INTERNAL_SERVER_ERROR, "INTERNAL_ERROR",
                     "Something went wrong", req, null);
    }

    private ResponseEntity<ErrorResponse> build(HttpStatus s, String code, String msg,
                                                HttpServletRequest req, Map<String, String> errors) {
        return ResponseEntity.status(s).body(
            new ErrorResponse(Instant.now(), s.value(), code, msg, req.getRequestURI(), errors));
    }
}

Spring picks the most specific matching handler, so ResourceNotFoundException wins over Exception.

4. Custom validation annotation

The most common meaning of “custom annotation” in interviews.

@Documented
@Constraint(validatedBy = AgeValidator.class)
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
public @interface ValidAge {
    String message() default "Age must be 18 or above";
    int min() default 18;
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}
public class AgeValidator implements ConstraintValidator<ValidAge, Integer> {
    private int min;

    @Override
    public void initialize(ValidAge ann) { this.min = ann.min(); }

    @Override
    public boolean isValid(Integer age, ConstraintValidatorContext ctx) {
        return age != null && age >= min;
    }
}
public class UserRequest {
    @NotBlank(message = "Name is required")
    private String name;

    @ValidAge
    private Integer age;
}

@PostMapping("/users")
public ResponseEntity<String> create(@Valid @RequestBody UserRequest req) { ... }

If age is 15, Spring throws MethodArgumentNotValidException and the handler above returns a 400 with {"errors": {"age": "Age must be 18 or above"}}.

5. Annotation-driven exception mapping

Put the HTTP status and error code on the exception class itself, and let one handler read it.

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface ApiError {
    HttpStatus status() default HttpStatus.INTERNAL_SERVER_ERROR;
    String code();
}

public abstract class AppException extends RuntimeException {
    protected AppException(String msg) { super(msg); }
}

@ApiError(status = HttpStatus.NOT_FOUND, code = "USER_NOT_FOUND")
public class UserNotFoundException extends AppException {
    public UserNotFoundException(Long id) { super("User not found: " + id); }
}

@ApiError(status = HttpStatus.CONFLICT, code = "EMAIL_EXISTS")
public class EmailAlreadyExistsException extends AppException { ... }
@ExceptionHandler(AppException.class)
public ResponseEntity<ErrorResponse> handleApp(AppException ex, HttpServletRequest req) {
    ApiError meta = AnnotatedElementUtils.findMergedAnnotation(ex.getClass(), ApiError.class);
    HttpStatus status = meta != null ? meta.status() : HttpStatus.INTERNAL_SERVER_ERROR;
    String code = meta != null ? meta.code() : "APP_ERROR";
    return build(status, code, ex.getMessage(), req, null);
}

A new error is now one small annotated class, and the handler never changes. Key ideas: @Retention(RUNTIME) makes the annotation readable by reflection, and @Target(TYPE) limits it to classes.

6. Annotation cheat sheet

Handling

AnnotationMeaning
@ExceptionHandlerMarks a method that handles specific exception types. Can take the exception, HttpServletRequest or WebRequest as parameters.
@ControllerAdviceGlobal component whose @ExceptionHandler, @InitBinder and @ModelAttribute methods apply to all controllers. Narrow with basePackages, assignableTypes or annotations.
@RestControllerAdvice@ControllerAdvice + @ResponseBody, so return values become JSON.
@ResponseStatusSets the HTTP status on an exception class or handler method. Fixed status, no dynamic body.
@ResponseBodyWrites the return value to the response body.
@Order / @PriorityOrdering when you have multiple advice classes.

Validation

AnnotationMeaning
@ValidTriggers bean validation on a @RequestBody or nested object. Failure throws MethodArgumentNotValidException.
@ValidatedSpring's variant. On a class it enables validation of @PathVariable and @RequestParam (throws ConstraintViolationException). Supports validation groups.
@NotNull, @NotBlank, @NotEmptyNot null; not null, empty or whitespace (strings); not null or empty (collections and strings).
@Size, @Min, @Max, @Email, @PatternSize, number range, email format, regex.
@ConstraintMarks an annotation as a validation constraint and links it to its validator.

Web and meta

AnnotationMeaning
@RestController@Controller + @ResponseBody.
@RequestBody, @PathVariable, @RequestParamBind the body, URL segment or query parameter.
@RetentionHow long a custom annotation lives (SOURCE, CLASS, RUNTIME). Use RUNTIME for reflection or validation.
@TargetWhere it can be placed (TYPE, METHOD, FIELD, PARAMETER).
@Documented, @InheritedInclude in Javadoc; subclasses inherit a class-level annotation.
@Slf4j (Lombok)Generates a log field.
@TransactionalRolls back on unchecked exceptions by default. Use rollbackFor = Exception.class for checked ones.

7. Interview questions

@ControllerAdvice vs. @RestControllerAdvice?

The second includes @ResponseBody, so handlers return JSON without annotating each method.

@ExceptionHandler in a controller vs. in advice?

In a controller it applies to that controller only. In advice it is global. A controller-level handler takes precedence for its own controller.

@Valid vs. @Validated?

@Valid is the Jakarta standard and cascades into nested objects. @Validated is Spring's, supports groups, and enables method-level validation when placed on a class.

Which exception does a failed @Valid @RequestBody throw?

MethodArgumentNotValidException. Failed @Validated path or query parameters throw ConstraintViolationException.

Checked or unchecked for custom business exceptions?

Usually unchecked (RuntimeException): @Transactional rolls back on them by default and you avoid throws clutter.

What happens if no handler matches?

It falls through to BasicErrorController at /error.

How do you avoid leaking internals?

Add a fallback @ExceptionHandler(Exception.class) that logs the stack trace and returns a generic message.

What is ProblemDetail?

Spring 6 / Boot 3 supports RFC 7807 (application/problem+json). Return ProblemDetail, or extend ResponseEntityExceptionHandler for standard handling of Spring MVC's own exceptions.

How do you handle exceptions thrown in filters?

@ControllerAdvice can't catch them because filters run before DispatcherServlet. Catch them in the filter, or delegate to a HandlerExceptionResolver.

Best practices: one global handler, a consistent error body, specific exception types, a generic fallback, and never expose stack traces to clients.
